# 요구사항 정의서 — Team Project PM Agent

> 관련 문서: [PLAN](PLAN.md) · [DATA_SPEC](DATA_SPEC.md) · [AGENTS](AGENTS.md) · [TEST_PLAN](TEST_PLAN.md)

## 1. 사용자

| 사용자 | 설명 | 주요 목적 |
|---|---|---|
| 팀원 (4명) | 팀 저장소에 커밋, PR, 이슈를 올리는 개발자 | 아침에 내 할 일과 막힌 일을 빠르게 확인 |
| 팀장 | 팀원 중 한 명, 리포트 승인 권한 보유 | 위험 요소를 먼저 보고, 잘못된 리포트가 나가지 않게 막기 |
| 운영자 | pm-agent 저장소 관리자 (해든) | 설정, 임계값 조정, 장애 대응 |

## 2. 사용자 스토리

- **US-1** 팀원으로서, 매일 아침 팀 채널에서 **어제 내가 한 일**이 정리된 것을 보고 스탠드업을 빠르게 끝내고 싶다.
- **US-2** 팀원으로서, **오늘 내가 처리할 이슈와 리뷰 요청**을 한눈에 보고 싶다.
- **US-3** 팀장으로서, **오래된 PR, 막힌 작업, 반복 실패하는 테스트**를 먼저 알고 싶다.
- **US-4** 팀장으로서, 리포트를 **발송 전에 확인하고 승인하거나 거절**하고 싶다.
- **US-5** 운영자로서, 필요할 때 **수동 실행**하거나 **주간 범위**로 리포트를 만들고 싶다.
- **US-6** 운영자로서, 위험 판정 **임계값을 코드 수정 없이** 바꾸고 싶다.

## 4. 비기능 요구사항

| ID | 항목 | 기준 |
|---|---|---|
| NFR-01 | 실행 시간 | generate job **5분 이내** |
| NFR-02 | 비용 | 1회 실행 LLM 비용 **$0.05 이하** (7d 모드 $0.2 이하) |
| NFR-03 | 권한 | 팀 저장소에는 **읽기 전용** 토큰만 사용, 쓰기 권한 없음 |
| NFR-04 | 비밀 관리 | 토큰, 웹훅, API 키는 GitHub Secrets에만 저장, 로그에 출력 금지 |
| NFR-05 | 신뢰성 | LLM 호출 실패 시 재시도 2회, 그래도 실패하면 **규칙 기반 리포트**로 대체 발송 |
| NFR-06 | 정확성 | 리포트 항목의 근거 링크 유효율 **100%**, 근거 없는 항목 **0개** |
| NFR-07 | 재현성 | fixtures만으로 네트워크 없이 전체 그래프를 실행할 수 있다 |
| NFR-08 | 개인정보 | LLM에는 커밋 메시지, 제목, 로그 일부만 전달하고 이메일 주소는 보내지 않는다 |
| NFR-09 | API 한도 | GitHub API 호출 1회 실행당 **300회 이하** (PAT 한도 5,000회/시간) |

## 5. 제약 사항

- 실행 환경은 GitHub Actions `ubuntu-latest`이며 상태를 저장하지 않는다. 이전 실행 정보가 필요하면 GitHub API에서 다시 조회한다.
- team-pm-agent 저장소는 public이다. 코드와 설정 파일에 민감 정보를 넣지 않는다.
- 팀 저장소는 수정하지 않는다(워크플로 추가 없음).

## 6. 인수 기준 (MVP 완료 조건)

1. 실제 팀 저장소를 대상으로 **평일 3일 연속** 자동 실행 → 팀장 승인 → Discord 발송이 성공한다.
2. 3일 동안 리포트에 **근거 없는 항목이 0개**다 (TEST_PLAN 5장 기준).
3. 규칙이 찾은 위험 요소가 리포트에서 **하나도 빠지지 않는다**.
4. 거절하면 발송되지 않는다.
